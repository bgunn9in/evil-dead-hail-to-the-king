# Evil Dead: Hail to the King — нативный перенос движка

[English description](README.md)

Неофициальная реконструкция движка на C++17 для современных Windows. Эталон
геймплея, сценариев, анимаций, камер и звука — версия Dreamcast. Отрисовка использует
**Vulkan через SDL3 GPU**. Проект находится в разработке; это не официальный
ремастер и не эмулятор консоли.

**В репозитории только исходники.** Графика, модели, шрифты, игровые сценарии,
звук, музыка, ролики, образы дисков, сохранения и готовые игровые пакеты исключены.
Полная таблица перевода оригинального текста также не публикуется. В исходниках
есть только подписи дополнительных меню движка. Игровые данные нужно подготовить
локально из собственной копии Dreamcast.

## Возможности

- Исполнение исходных JPC-сценариев и поддержка обеих глав.
- Фиксированные камеры, коллизии, перекрытия, анимации, бой, инвентарь, предметы,
  двери и сохранения.
- Клавиатура и современные геймпады: переназначение, мёртвые зоны и вибрация.
- Русский и английский интерфейс при наличии соответствующих локальных ресурсов.
- Выбор разрешения, широкие экраны с сохранением композиции кадра, сканлайны и плёнка.
- PNG для изображений и масок, музыка FLAC без потерь, ролики AV1. Декодеры встроены.

Текущая целевая платформа — Windows x64. Проверка Linux отложена. Полное совпадение
с растеризацией Dreamcast не заявляется; отдельные визуальные и коллизионные
граничные случаи требуют дальнейшего сравнения.

## Сборка Windows

Нужны Visual Studio с C++ x64 и Windows SDK, CMake 3.24+, Git, Python 3.10+ с pip.
Pillow используется инструментами изображений, FFmpeg/FFprobe — подготовкой медиа.
Скрипты загружают закреплённые исходники SDL3 3.4.18 и dav1d 1.5.2 с проверкой SHA-256.

```powershell
.\scripts\build.ps1
```

Без игровых данных команда собирает исходники и пропускает полный запуск игровых
тестов. EXE находится в `build/episode/Release/evil-dead-scene.exe`. Для игры ему
понадобится подготовленный профиль ресурсов. Исходник шейдеров и восемь программ
SPIR-V входят в репозиторий как код движка; компилятор шейдеров для обычной сборки
не нужен. dr_flac включён с лицензией автора.

## Локальные ресурсы и проверки

`tools/extract_dreamcast.py` извлекает файлы из собственного GDI-образа в **новый**
каталог. CHD предварительно распаковывается локально своим `chdman`.
`export_dreamcast_*`, `import_dreamcast_audio.py` и `import_dreamcast_runtime.py`
преобразуют подготовленные компоненты; контракты входных данных доступны через
`--help`. Единой команды подготовки полного профиля из чистого диска сейчас нет.

Профиль ресурсов по умолчанию — `build/episode/assets/`. Полный набор тестов также
требует исходный 1x-профиль в `build/dreamcast-upscale-native-source-20261028/assets/`.
Оба каталога исключены из Git. Импортёр привязан к конкретному проверенному
извлечению Dreamcast; произвольные издания или изменённые профили не равнозначны.
Не редактируйте запечатанные ресурсы на месте: профили могут разделять неизменяемые
файлы через жёсткие ссылки. Преобразования выполняются в новые каталоги.

После сборки зависимостей можно выбрать внешние пути:

```powershell
cmake -S . -B build/episode -A x64 `
  -DTEST_ASSETS="C:/private/game-assets" `
  -DNATIVE_FIXTURE_ASSETS="C:/private/original-fixture"
cmake --build build/episode --config Release
ctest --test-dir build/episode -C Release --output-on-failure
```

После сборки небольшой набор проверяется **без ресурсов игры**:

```powershell
ctest --test-dir build/episode -C Release --output-on-failure `
  -R "^(input|native-input-queue|ground|door-policy|jpc|source-floor-query|save-file)$"
python -B -m unittest discover -s tools -p test_archive_package.py
python -B -m unittest discover -s tools -p test_create_release_torrent.py
```

Полный CTest и многие Python-тесты экспортёров требуют локальные оригинальные данные.
Эти игровые тестовые наборы в исходники не входят.

## Структура и уведомления

- `runtime/` — движок, совместимость, шейдеры и C++-тесты.
- `tools/` — преобразование, исследовательские утилиты, локализация и упаковка.
- `scripts/` — закреплённые зависимости и Windows-пакеты.
- `localization/ui-ru.json` — подписи дополнительных меню самого движка.

[Подготовка Windows-пакета](README-package.md) работает с собственными локальными
данными. Ресурсы и готовые игровые пакеты не коммитят и не прикладывают к релизам
репозитория. [Уведомления о зависимостях](THIRD_PARTY_NOTICES.md) описывают лицензии.
Общая лицензия на исходники пока не выбрана; сторонние файлы сохраняют свои условия.
Название игры и исходный игровой контент принадлежат их правообладателям.
